# FramePulse — сайт на GitHub Pages

Сайт — статический: главная страница, мобильная версия, характеристики, офлайн-демо 7.3.0 и кнопки загрузки установщика из GitHub Releases. После публикации не нужны ни Arena, ни включённый ПК, ни свой сервер. Сайт остаётся доступным, пока репозиторий и GitHub Pages включены и работает сама площадка.

## Первая публикация

1. Создай **публичный пустой репозиторий** на GitHub, например `framepulse-site`. Не добавляй README при создании, если загружаешь через `git push`.
2. Загрузи содержимое этого архива **в корень репозитория**. Нужны `site/`, `.github/workflows/pages.yml`, `release.json` и `prepare_pages.py`. Папка `.github` обязательна, не пропускай её. Установщик в исходники не загружай.
3. В репозитории открой **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. В **Releases → Draft a new release** создай тег **`v7.3.0`** на ветке `main`, прикрепи **`FramePulse-7.3.0-Setup-x64.exe`** и нажми **Publish release**. Релиз должен быть опубликован, а не сохранён черновиком. Имя файла не меняй.
5. В **Actions** дождись зелёного статуса «Публикация FramePulse». Если первый запуск до настройки Pages был красным, после шагов 3–4 на странице workflow нажми **Run workflow**. Точный адрес появится в **Settings → Pages**. Для репозитория `framepulse-site` стандартный вид: `https://ТВОЙ-ЛОГИН.github.io/framepulse-site/`.

### Загрузка исходников через Git

Открой терминал **в распакованной папке** с этим README. Нужно, чтобы Git был установлен и настроен доступ к твоему GitHub. Замени `ТВОЙ-ЛОГИН` на свой логин:

```sh
git init -b main
git add .
git commit -m "Publish FramePulse website"
git remote add origin https://github.com/ТВОЙ-ЛОГИН/framepulse-site.git
git push -u origin main
```

Затем выполни шаги 3–5 в браузере. Не присылай пароль или токен в чат.

## Следующие релизы

Обнови версию и SHA‑256 в `release.json`, название выпуска и ссылки в `site/index.html`, при необходимости `site/demo/index.html` и скриншот. Опубликуй установщик с новым именем под соответствующим тегом `vX.Y.Z`. Workflow проверяет SHA‑256 файла из релиза перед публикацией и автоматически превращает локальные ссылки в адреса GitHub Releases.

Это механизм публикации **сайта и файла**, а не обновлятор в программе. Для обновлений внутри FramePulse ещё нужно собрать версию приложения с отдельной проверкой подписи манифеста. Файл `release.json` сам по себе не является подписанным манифестом.
